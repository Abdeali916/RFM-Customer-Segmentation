# Data Dictionary

## 1. Dataset Overview

This data dictionary documents the fields used in the **Online Retail** dataset for the RFM Customer Segmentation and E-commerce Analytics project.

The dataset contains historical transaction-level records from an online retail business. Each row represents a transaction line for a product purchased on an invoice.

The data dictionary is intended to make the dataset and the analytical process easier to understand and reproduce.

---

## 2. Source Dataset

**Dataset:** Online Retail

**Primary use in this project:** Customer purchasing behavior, sales analysis, and RFM customer segmentation.

**Granularity:** Transaction-line level.

**Number of rows in source file:** 541,909

**Number of columns:** 8

---

## 3. Original Dataset Columns

| Column | Description | Data Type |
|---|---|---|
| `InvoiceNo` | Unique invoice number identifying a transaction. Invoice numbers beginning with 'C' represent cancellations in the original dataset. | `object` |
| `StockCode` | Unique code identifying a product/item. | `object` |
| `Description` | Description or name of the product purchased. | `object` |
| `Quantity` | Number of units of the product included in the transaction. | `int64` |
| `InvoiceDate` | Date and time when the transaction was recorded. | `datetime64[ns]` |
| `UnitPrice` | Price charged for one unit of the product. | `float64` |
| `CustomerID` | Unique identifier assigned to a customer. Some transactions may have a missing CustomerID. | `float64` |
| `Country` | Country associated with the customer/transaction. | `object` |

---

## 4. Column Details

### `InvoiceNo`

Unique invoice number associated with a transaction.

Invoice numbers beginning with **`C`** indicate cancelled transactions in the original dataset.

**Used for:**
- Transaction identification
- Order/invoice analysis
- Cancellation analysis

---

### `StockCode`

Unique identifier assigned to a product.

**Used for:**
- Product-level analysis
- Identifying best-selling products
- Product revenue analysis

---

### `Description`

Text description of the product associated with the transaction.

**Used for:**
- Product identification
- Product-level business analysis

---

### `Quantity`

Number of units of a product purchased in the transaction.

**Used for:**
- Sales volume analysis
- Product performance analysis
- Revenue calculation

---

### `InvoiceDate`

Date and time when the transaction was recorded.

**Used for:**
- Time-series analysis
- Monthly sales analysis
- Customer recency calculation
- Purchase trend analysis

---

### `UnitPrice`

Price of a single unit of the product.

**Used for:**
- Revenue calculation
- Product pricing analysis
- Transaction value analysis

---

### `CustomerID`

Unique identifier associated with a customer.

**Used for:**
- Customer-level analysis
- Customer purchase frequency
- Customer revenue analysis
- RFM calculations
- Customer segmentation

**Important:** Missing CustomerID values need to be handled before customer-level analysis.

---

### `Country`

Country associated with the customer/transaction.

**Used for:**
- Geographic analysis
- Revenue by country
- Customer distribution by country
- Market-level analysis

## 5. Derived / Calculated Fields

The project also creates analytical fields from the original transaction data.

### `Revenue`

Represents the revenue generated by a transaction line.

**Calculation:**

```text
Revenue = Quantity × UnitPrice
```

**Used for:**
- Revenue analysis
- Customer monetary value
- Product revenue analysis
- Country revenue analysis

---

### `Recency`

Measures how recently a customer made a purchase.

A customer's most recent transaction is used to determine the number of days since their last purchase relative to the selected analysis/reference date.

**Interpretation:**

Lower Recency → More recent customer activity.

Higher Recency → Customer has been inactive for longer.

---

### `Frequency`

Measures how frequently a customer purchases.

Depending on the project calculation, this is represented at the customer level using the number of distinct purchase invoices/orders associated with the customer.

**Interpretation:**

Higher Frequency → More frequent purchasing behavior.

---

### `Monetary`

Measures the total revenue generated by a customer.

**Calculation:**

```text
Monetary = Sum of Revenue for the Customer
```

**Interpretation:**

Higher Monetary value → Greater customer contribution to revenue.

---

### `RFM Score`

A combined score representing a customer's Recency, Frequency, and Monetary behavior.

The individual RFM measures are scored and combined according to the scoring methodology implemented in the project.

---

### `Customer Segment`

A business-oriented customer category derived from the RFM score.

The project uses RFM characteristics to identify customer groups such as:

- High-value customers
- Loyal customers
- Potential high-value customers
- Recent customers
- At-risk customers
- Inactive customers

The exact classification is determined by the segmentation logic implemented in the project.

---

## 6. Data Quality Considerations

The following data quality issues are considered during data preparation:

- Missing `CustomerID` values
- Cancelled transactions identified through `InvoiceNo`
- Duplicate transaction records
- Invalid or non-positive `Quantity` values
- Invalid or non-positive `UnitPrice` values
- Missing product descriptions
- Data type conversion for `InvoiceDate`
- Revenue calculation validation

These checks are performed before using the data for customer-level and RFM analysis.

## 8. RFM Metric Summary

| Metric | Measures | Business Interpretation |
|---|---|---|
| Recency | How recently a customer purchased | Customer activity |
| Frequency | How often a customer purchased | Customer engagement |
| Monetary | How much a customer spent | Customer value |

Together, these metrics provide a behavioral view of customer value and allow customers to be grouped into actionable segments.
